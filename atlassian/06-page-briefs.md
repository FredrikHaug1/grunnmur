# 06 Page Briefs

# **1 About this document**

This document defines how we create page briefs for Videocation.no.

A page brief must be completed before a page is designed, written or implemented. The purpose is to make sure every page has a clear job, a defined audience, relevant proof, agreed messaging and measurable success criteria.

Confluence documents the brief. Jira manages the delivery work.

# **2 When to create a page brief**

Create a page brief when we are:

* Creating a new page
* Rewriting an important existing page
* Building a campaign landing page
* Creating a solution page
* Creating a diagnostic tool page
* Creating a high-value resource page
* Making major changes to homepage, navigation or demo flow

Small copy changes, bug fixes or visual adjustments do not need a full page brief.

# **3 Page brief principles**

Every page should answer:

1. Who is this page for?
2. What problem does the visitor have?
3. What do we want the visitor to understand?
4. What proof do we need?
5. What should the visitor do next?
6. How will we measure success?

A page should not be created just because we have content. It should exist because it supports either qualified B2B lead generation or B2B brand building.

# **4 Page Brief Template**

## **4.1 Page name**

Add the working title of the page.

## **4.2 Page owner**

Name the person responsible for the page.

## **4.3 Status**

Use one of the following:

* Draft
* Ready for review
* Approved
* In design
* In development
* In QA
* Live
* Needs revision

## **4.4 Related OKR**

Select the primary OKR the page supports:

* Objective 1: Generate more qualified B2B leads for sales
* Objective 2: Build Videocation as a brand in the B2B market
* Both

## **4.5 Page type**

Select one:

* Homepage
* Solution page
* Platform page
* Programme/content page
* Customer story
* Resource article
* Report page
* AI analysis tool page
* Demo/contact page
* Campaign landing page
* Other

## **4.6 Primary audience**

Who is this page primarily for?

Examples:

* HR leader
* L&D manager
* CEO / General Manager
* Business leader
* Department manager
* Existing customer
* Procurement / IT stakeholder

## **4.7 ICP / segment**

Which company type is this page most relevant for?

Examples:

* Companies with 100+ employees
* Large distributed organisations
* Companies with leadership development needs
* Companies rolling out AI competence
* Companies needing compliance or HMS training

## **4.8 Buyer journey stage**

Select one:

* Awareness
* Relevance
* Understanding
* Trust
* Evaluation
* Conversion
* Brand memory

## **4.9 Main buyer problem**

Describe the problem in the buyer’s own language.

Examples:

* “Our leaders need a common language.”
* “We need to roll out AI competence across the company.”
* “Employees are not completing training.”
* “We need to show that learning supports business goals.”
* “Our LMS is not creating enough value.”

## **4.10 Buyer’s current alternative**

What might the buyer do instead of choosing Videocation?

Examples:

* Buy a course library
* Use an existing LMS
* Run one-off workshops
* Ask managers to solve it locally
* Build internal training manually
* Do nothing

## **4.11 Desired business outcome**

What outcome does the buyer want?

Examples:

* Better leadership practice
* Shared competence across teams
* Higher completion of training
* More consistent onboarding
* Reduced compliance risk
* More measurable learning impact

## **4.12 Primary message**

One sentence that captures what the page must communicate.

Example:

“Videocation helps companies build structured competence programmes that employees complete and managers can follow up.”

## **4.13 Secondary messages**

List 3–5 supporting messages.

Examples:

* Norwegian expert-led content
* Structured programmes, not random course consumption
* Practical tools and reflection exercises
* Progress tracking and reporting
* Support for implementation and follow-up

## **4.14 Key objections to address**

What might the buyer worry about?

Examples:

* “Will employees actually use this?”
* “Is this just another course library?”
* “Can we measure progress?”
* “Is the content relevant for our business?”
* “Will this work alongside our existing LMS?”
* “How much time will this require from managers?”

## **4. 15 Proof we can use**

### **Customer proof**

Customer logos, case studies, testimonials or results.

### **Expert proof**

Expert names, credentials, course examples or video clips.

### **Product proof**

Screenshots, dashboards, learning paths, demo clips or programme examples.

### **Methodology proof**

Models, frameworks, research-based principles or implementation approach.

### **Data/results**

Completion rates, engagement data, customer outcomes or relevant benchmarks.

### **Visual assets needed**

List what the page requires.

Examples:

* Product screenshots
* Learning journey diagram
* Expert portraits
* Customer logo
* Customer quote
* Programme example
* Video thumbnail
* AI analysis preview
* Data visualisation

# **5 Recommended page structure**

Use the relevant structure below.

## **5.1 Homepage structure**

Recommended sections:

1. Hero
2. Problem section
3. Solution overview
4. Use-case routing
5. Product proof
6. Expert and content proof
7. Customer proof
8. Methodology
9. Free analysis section
10. Final CTA

## **5.2 Solution page structure**

Recommended sections:

1. Specific hero
2. Buyer pain points
3. Our approach
4. What the customer gets
5. Example programme or learning path
6. Proof
7. Related resources
8. CTA

## **5.3 AI analysis tool page structure**

Recommended sections:

1. Clear value proposition
2. Explanation of how the analysis works
3. Organisation number / company input
4. Company-specific preview before email capture
5. Explanation of full report
6. Data sources and assumptions
7. Privacy and contact explanation
8. Email capture
9. Confirmation and next step

## **5.4 Resource page structure**

Recommended sections:

1. Clear title and problem framing
2. Practical insight
3. Point of view
4. Examples
5. Internal links to relevant solution pages
6. CTA based on intent level
7. Related content

## **5.5 Demo/contact page structure**

Recommended sections:

1. Clear headline
2. Short explanation of what happens after submission
3. Short form or meeting booking
4. Trust proof
5. Alternative contact option
6. Privacy reassurance

# **6 CTA requirements**

## **6.1 Primary CTA**

What is the main action?

Examples:

* Book a demo
* Get a free benchmark analysis
* Talk to us about leadership development

## **6.2 Secondary CTA**

What should lower-intent visitors do?

Examples:

* See example program
* Explore resources
* Read customer story
* See how it works

## **6.3 CTA principle**

Avoid vague CTAs such as:

* Learn more
* Submit
* Get started

Use specific CTAs that explain the value of the next step.

## **7.1 Primary keyword or search topic**

Add the main search topic.

## **7.2 Secondary keywords**

Add related search terms.

## **7.3 Search intent**

Describe what the visitor is trying to understand.

## **7.4 SEO title**

Draft title.

## **7.5 Meta description**

Draft description.

## **7.6 Internal links to include**

List relevant pages this page should link to.

## **7.7 Pages that should link to this page**

List pages that should point to this page.

# **8 Tracking requirements**

Define what should be measured.

Recommended fields:

* Page views
* CTA clicks
* Form starts
* Form completions
* AI analysis starts, if relevant
* Scroll depth
* Resource downloads
* Demo bookings
* HubSpot lead type
* Source / UTM
* Sales status

## **8.1 Primary KPI**

The most important measure for this page.

## **8.2 Secondary KPIs**

Supporting measures.

## **8.3 Assisted conversion metrics**

How the page may influence conversion even if it is not the final conversion page.

## **8.4 Acceptance criteria**

A page is ready for design and development when:

* Primary audience is clear
* Main buyer problem is defined
* Primary message is approved
* Proof requirements are identified
* CTA strategy is defined
* SEO intent is documented
* Tracking requirements are defined
* Open questions are resolved or assigned
* Related Jira work is linked
