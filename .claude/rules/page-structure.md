# Page structure

## The page brief gate

**No page moves into design or development without an approved page brief.**

A brief is required when creating a new page, rewriting an important existing page,
building a campaign landing page, creating a solution page, creating a diagnostic
tool page, creating a high-value resource page, or making major changes to the
homepage, navigation or demo flow.

Small copy changes, bug fixes and visual adjustments do not need one.

A page is ready for design and development when all of these are true:

- Primary audience is clear
- Main buyer problem is defined
- Primary message is approved
- Proof requirements are identified
- CTA strategy is defined
- SEO intent is documented
- Tracking requirements are defined
- Open questions are resolved or assigned
- Related Jira work is linked

A page exists because it supports qualified B2B lead generation or B2B brand
building — never because content happens to exist.

## Section order by page type

### Homepage

1. Hero
2. Problem section
3. Solution overview
4. Use-case routing
5. Product proof
6. Expert and content proof
7. Customer proof
8. Methodology
9. Free analysis section
10. Final CTA

The hero answers three questions within seconds: who is this for, what problem do we
solve, what outcome do we create. Be concrete — not
"Empowering organizations through next-generation learning solutions."

### Solution page

1. Specific hero — names the exact problem and audience
2. Buyer pain points
3. Our approach
4. What the customer gets
5. Example programme or learning path
6. Proof
7. Related resources
8. CTA

### AI analysis tool page

1. Clear value proposition
2. Explanation of how the analysis works
3. Organisation number / company input
4. Company-specific preview **before** email capture
5. Explanation of full report
6. Data sources and assumptions
7. Privacy and contact explanation
8. Email capture
9. Confirmation and next step

### Resource page

1. Clear title and problem framing
2. Practical insight
3. Point of view
4. Examples
5. Internal links to relevant solution pages
6. CTA based on intent level
7. Related content

### Demo / contact page

1. Clear headline
2. Short explanation of what happens after submission
3. Short form or meeting booking
4. Trust proof
5. Alternative contact option
6. Privacy reassurance

## Show, then tell

Lead with a visual example, then explain it — not the reverse:

1. Screenshot or diagram
2. Short heading
3. One-sentence explanation
4. Supporting bullets
5. CTA or link to learn more

Make the invisible visible. Competence development is abstract; show what the
customer actually gets — example learning path, example course page, admin
dashboard, reporting view, implementation timeline, manager follow-up flow.

## Buyer journey stages

Every brief names one: Awareness · Relevance · Understanding · Trust · Evaluation ·
Conversion · Brand memory.
